# 素材审核与发布排期 Agent — 需求文档

> 文档性质：业务需求说明，不包含实现方案与业务代码。  
> 版本：v0.1

## 1. 用户是谁

直接用户是**内容团队**，实际使用者为负责素材审核、发布排期和排期确认的成员，例如内容运营、审核人员和排期负责人。

用户的核心诉求是：

- 快速知道哪些素材待处理、分别卡在哪里；
- 在不违反审核规则和硬性发布时间要求的前提下，得到可执行的建议时段；
- 对风险、冲突和变更保持控制权，由自己做最终确认；
- 只生成排期草稿，避免误发布。

## 2. 目标是什么

根据素材信息、发布时间要求、已有排期和审核规则，帮助内容团队：

1. 找出待处理素材，避免漏审、漏排；
2. 对每项素材给出明确的审核状态和可理解的风险原因；
3. 在可用时段内形成无冲突的发布排期建议；
4. 将需要用户决定的事项集中列为待确认项；
5. 仅在符合规则且完成必要确认后保存排期草稿；
6. 保证草稿保存结果真实、可追溯，重复提交不产生重复草稿。

最终目标是形成**无冲突、可确认、只保存为草稿**的发布排期，而不是直接发布内容。

## 3. 输入

| 输入 | 说明 | 要求 |
| --- | --- | --- |
| 素材 ID、素材元数据 | 用于唯一标识素材，并判断素材类型、渠道、内容属性和审核所需字段 | 素材 ID 必须唯一；审核规则要求的字段必须完整 |
| 发布时间要求 | 用户对发布时间的硬性要求和偏好，例如最早/最晚时间、固定时间、指定时间窗、发布顺序 | 必须区分硬性要求与可调整偏好；时间需明确时区 |
| 已有排期 | 已存在的排期记录及其占用时段，用于判断冲突 | 需包含时段、时区及对应素材信息 |
| 审核规则 | 判断素材是否可发布、是否需要补充信息或人工确认的规则 | 规则应能给出命中原因；规则版本需可追溯 |

补充说明：

- **硬性发布要求**是用户明确声明不可擅自变更的时间约束。
- 未明确标注为硬性或偏好的时间要求，不得默认为可自由调整；无法判断时应按保守方式处理并请求确认。
- 缺失审核所需的关键字段时，视为素材信息不足，不得推测或补造。

## 4. 输出

对每一项素材，输出以下信息：

| 输出项 | 内容要求 |
| --- | --- |
| 素材 ID | 与输入一致，确保结果可对应到具体素材 |
| 审核状态 | 至少区分：通过、信息不足、规则风险、待确认 |
| 风险原因 | 命中规则、缺失字段、冲突情况或需人工判断的具体原因；无风险时明确标注“无” |
| 建议时段 | 满足时间要求的可发布时段；存在冲突时应同时给出替代时段 |
| 待确认项 | 需要用户决定或补充的事项，说明确认对象、可选方案及影响 |
| 草稿保存状态 | 未保存、已保存或保存失败；成功时附草稿标识，失败时附失败原因 |

输出要求：

- 每项素材都必须有审核状态和草稿保存状态，不得省略或只在成功时返回；
- 建议时段必须带时区，并与已有排期使用统一时间口径比较；
- 待确认项必须具体到“确认什么”，不能只写“请确认”；
- 不得将“已生成建议”表述为“已保存草稿”或“已发布”。

## 5. 范围

### 5.1 做什么

- 接收并校验素材、发布时间要求、已有排期和审核规则；
- 识别待处理素材，并逐项给出审核状态；
- 检查素材信息完整性，列出缺失字段；
- 按审核规则判断风险，返回规则命中原因；
- 查询已有排期，检测目标时段冲突；
- 在冲突时查询并展示替代时段；
- 汇总需要用户确认的事项，等待用户明确确认；
- 在满足规则和确认要求后，通过 `save_draft` 保存排期草稿；
- 对相同素材和相同最终时段的重复提交做幂等处理；
- 如实返回草稿保存成功、未保存或失败的状态。

### 5.2 不做什么

- **不真实发布内容**，不调用任何发布渠道，不产生线上发布结果；
- **不擅自改变硬性发布要求**，包括发布时间、时间窗、发布顺序等；
- 不在素材信息不足时强行排期或补造缺失信息；
- 不隐藏、弱化或跳过审核规则命中的风险；
- 不在时段冲突时自动改期并保存；
- 不在用户未确认时替用户做最终决定；
- 不重复创建相同素材、相同最终时段的草稿；
- 不在 `save_draft` 失败时返回成功或虚构草稿标识；
- 不负责素材创作、内容编辑、渠道账号管理和实际发布执行。

## 6. 业务规则与约束

### 6.1 只保存草稿

Agent 的所有写操作仅限于保存排期草稿。草稿不等同于已发布内容，也不得触发任何真实发布动作。

### 6.2 硬性发布要求受保护

未经用户明确确认，不得修改硬性发布时间要求。发现硬性要求与可用时段冲突时，应说明冲突并请求用户决定；即使用户确认调整，也应保留原要求、调整后要求和确认记录。

### 6.3 信息不足不得强行排期

审核规则要求的关键字段缺失时：

- 审核状态为“信息不足”；
- 列出全部已知的缺失字段；
- 要求用户补充信息；
- 不保存草稿，不虚构字段值，不输出确定性的最终排期。

### 6.4 规则风险必须显式返回

命中审核规则时，必须返回风险原因，至少包含命中规则和业务解释。不得静默保存。按规则可选择：

- 不保存草稿；或
- 进入人工确认流程，在用户明确确认前保持未保存状态。

### 6.5 时段冲突必须由用户确认

目标时段与已有排期冲突时：

- 返回冲突时段及冲突对象；
- 查询并展示可替代时段；
- 在用户明确确认前，不改变最终时段，不保存草稿；
- 禁止自动改期后直接保存。

### 6.6 重复提交幂等

以“相同素材 ID + 相同最终时段”为幂等判断依据。相同请求重复提交时，只保留一份草稿，并返回已有草稿或等价的幂等结果，不得新增重复草稿。

### 6.7 保存结果必须真实

`save_draft` 返回失败、超时或结果不明确时，必须返回“保存失败”状态并说明原因；若结果不明确，还应标注“保存结果未知，需核对”，在核实前不得视为成功。不得标记为已保存，不得提供虚构的草稿标识。

### 6.8 确认必须明确且可追溯

用户确认必须是针对具体素材和具体最终时段的明确同意，不能由沉默、默认选项或模糊表述推断。最终时段发生变化后，原有确认失效，需重新确认。

## 7. 成功标准

以下 6 条必须全部满足，缺一不可。

### 7.1 正常排期

素材无审核风险、信息完整，且目标时段空闲时，Agent 应给出通过状态和可用建议时段，并能够成功保存排期草稿。

### 7.2 素材信息不足

素材信息不足时，不能强行排期；必须列出缺失字段并要求用户补充，且不得保存草稿或虚报保存成功。

### 7.3 规则风险

素材命中审核规则时，必须返回具体风险原因，不得静默保存草稿；应不保存草稿，或先请求人工确认。

### 7.4 时段冲突

目标时段冲突时，必须查询并给出替代时段，但必须先请求用户确认；用户确认前不得改变最终时段，也不能自动改期保存。

### 7.5 重复提交

相同素材与相同最终时段的重复提交，只能产生一份草稿，不得因重复提交新增草稿。

### 7.6 保存失败

`save_draft` 工具失败时，必须返回失败状态和失败原因，不能虚报保存成功，也不能返回不存在的草稿标识。

## 8. 验收点

| 编号 | 验收场景 | 通过条件 |
| --- | --- | --- |
| AC-01 | 正常素材 + 空闲时段 | 审核状态为通过；无风险原因；建议时段满足发布时间要求；草稿保存成功并返回草稿标识 |
| AC-02 | 缺少审核所需字段 | 审核状态为信息不足；完整列出缺失字段；要求补充；不保存草稿，不虚构字段值 |
| AC-03 | 素材命中审核规则且规则要求拦截 | 返回命中规则和风险原因；不保存草稿；保存状态明确为未保存 |
| AC-04 | 素材命中审核规则但允许人工确认 | 返回风险原因并进入待确认；用户确认前不保存；确认后才可继续，且确认对象与素材、时段一致 |
| AC-05 | 目标时段与已有排期冲突 | 返回冲突对象和冲突时段；给出至少一个替代时段；用户未确认前不改变最终时段、不保存 |
| AC-06 | 冲突后用户拒绝替代方案 | 不保存草稿；原硬性发布时间要求保持不变；明确返回未保存状态 |
| AC-07 | 冲突后用户明确确认替代时段 | 仅按确认后的最终时段保存一次草稿；保存结果与确认内容一致 |
| AC-08 | 相同素材 + 相同最终时段重复提交 | 只存在一份草稿；重复请求返回同一草稿或等价幂等结果；草稿数量不增加 |
| AC-09 | `save_draft` 返回失败或结果不明确 | 返回保存失败状态和失败原因；结果不明确时标注需核对；无成功提示；无虚构草稿标识；不声称草稿已保存 |
| AC-10 | 全流程检查 | 不产生任何真实发布动作；所有素材均有审核状态、风险原因、建议时段、待确认项和草稿保存状态 |
| AC-11 | 硬性发布要求保护 | 未经用户明确确认，任何硬性发布时间要求均未被修改；发生调整时可追溯原要求、新要求和确认记录 |
| AC-12 | 确认有效性 | 模糊、默认或针对其他时段的确认不被当作有效确认；时段变更后要求重新确认 |

## 9. 验收结论

只有 AC-01 至 AC-12 全部通过，且确认没有任何真实发布行为，才能认定本次需求验收通过。任一条失败，尤其是虚报保存成功、擅自改期、擅自修改硬性要求或产生重复草稿，均视为不通过。

## 10. 补充说明（候选人）

- 我理解“硬性要求”的核心是不可在无确认时变更；但确认后变更也应保留审计记录。
- AC-06 用户拒绝替代方案后，Agent 可以先停留在未保存状态，给用户新的替代时段选项，不直接终止。
- 本项目的“发布”仅指排期草稿，不应被理解为内容发布。
