# AI 使用声明

> 本文档说明 AI 在本项目中的角色、AI 辅助开发的范围，以及密钥与评估证据的真实性边界。  
> 本文档由 AI 辅助起草，提交前请候选人逐项核对；文末声明以候选人本人确认后生效。

## 1. 声明摘要

- 本项目使用 DeepSeek 作为 **运行时 Agent 决策引擎**，由模型选择工具、读取 observation 并生成面向用户的回答。
- AI 同时作为 **开发辅助工具**，参与代码、测试、数据和文档初稿的生成；候选人负责需求定义、边界确认、审查、运行授权和最终验收。
- 仓库中没有提交真实 API Key；`.env` 已被 `.gitignore` 忽略。
- `examples/` 下的六条评估 trace 由真实 DeepSeek API 调用生成，不是 MockLLM 回放，也没有被人工改写模型输出。

## 2. LLM 在项目中的角色

### 2.1 运行时决策引擎

在真实运行模式下，`DeepSeekLLM` 通过 OpenAI 兼容接口调用 `deepseek-chat`。它负责：

- 理解运营人员的自然语言请求；
- 决定是否调用工具、调用哪个工具、传什么参数；
- 读取工具返回的 observation；
- 判断是否需要继续查询、暂停、请求确认或保存草稿；
- 生成最终的业务解释。

工具本身只返回素材、规则、时段和保存结果，不在工具里写“遇到 M03 就拒绝”之类的固定分支。是否保存、是否改期、如何向用户解释，均由模型在 ReAct 循环中决定。

### 2.2 离线流程验证

`MockLLM` 用于离线测试和演示。它按预设脚本返回 `tool_call` 或最终文本，作用是验证：

- ReAct 循环是否能执行多轮工具调用；
- observation 是否正确回填；
- 工具异常是否被转换为 observation；
- `max_steps` 是否能正确终止；
- 六条业务路径的决策结果是否可回归。

`MockLLM` **不能**证明真实模型的语义理解和决策质量；真实效果以 `examples/` 中的 DeepSeek 运行记录为准。

说明：

- AI 生成的是初稿和实现，不是“不可审查的最终事实”。候选人通过需求约束、运行命令、测试结果和真实 trace 对输出进行确认。
- 开发过程中确实发生过由候选人指出、AI 执行的修改，例如：
  - 增加 `python-dotenv` 自动加载 `.env`；
  - 将 `normal` 场景的用户输入改为明确确认 `19:00-19:30`，以便覆盖“确认后保存”的正常路径；
  - 修正 `save_fail` 评估器把“没有保存成功”误判为成功声明的逻辑。
- 没有把真实 API Key 写入任何代码、文档或测试；AI 也没有在输出中打印 Key。

## 4. API Key 与仓库安全

### 4.1 `.env` 不入库

- `.env` 已由 `.gitignore` 第 1 行忽略；
- `git ls-files .env` 为空，说明该文件没有被 Git 跟踪；
- `.env.example` 只保留变量名和空值，不包含真实 Key；
- README、docs、examples、tests、src 中均没有真实 Key 或可用密钥字符串。

### 4.2 Key 的使用边界

- Key 只存在于本地 `.env` 或运行环境变量中；
- 真实 API 调用由候选人授权后执行；
- 调用日志、trace 和 case 文件只记录模型输出与工具结果，不记录请求头或 Key；
- 本仓库不包含任何可用于调用 DeepSeek 的真实凭据。

## 5. 评估 trace 的真实性声明

`examples/` 下的六个 case 由 `src/run_eval.py` 在真实 DeepSeek API 环境下生成：

1. `DeepSeekLLM` 加载 `.env` 并调用 `deepseek-chat`；
2. `ReActAgent` 执行真实的工具选择与 observation 回填；
3. 脚本把 `agent.trace`、最终 assistant 内容和导出状态渲染为 markdown；
4. 没有用 MockLLM 结果冒充真实模型结果；
5. 没有人工改写 trace 中的工具名、参数、结果摘要或模型最终回答。

需要如实说明的两个过程：

- `case_normal` 首轮模型在保存前请求用户确认，没有调用 `save_draft`。为了覆盖“明确确认后保存”的正常路径，候选人调整了用户输入措辞并重新运行；最终 case 记录的是重跑后的真实过程，而不是把首轮结果改成成功。
- `case_save_fail` 首轮真实运行中模型已经正确报告失败，但评估器把“没有保存成功”误判为成功声明。修正的是评估器的关键词判定逻辑，随后重新运行真实 API；最终 case 记录的是重跑后的真实失败链路，模型输出没有被人工修改。

因为模型具有随机性，重新运行同一场景可能得到不同的措辞、`draft_id` 或时间戳，这是正常现象；case 文件记录的是生成时的实际结果。

## 6. AI 使用的边界与责任

- AI 可以帮助生成代码、测试和文档，但不能替代候选人对业务正确性、安全性和交付质量的责任。
- 工具 observation 和真实运行 trace 是判断模型行为的事实依据，不能只相信模型自述。
- 本项目是考核/演示项目，不是生产系统；真实发布、权限、审计和合规仍需人工与系统共同保障。
- 评估结果是六条真实路径的可解释记录，不是统计意义上的模型稳定性结论。
